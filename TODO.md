- [ ] **Native Windows has no control API, and no ratatui frontend.** `control.socket_supported()` is `hasattr(socket, "AF_UNIX")`, and **stock CPython on Windows never exposes `AF_UNIX`** — the OS has supported it since Windows 10 1803, but CPython's PR ([bpo-33408](https://bugs.python.org/issue33408)) is still unmerged. Consequences on a native Windows host: the engine does not bind the control socket (`src/main.py` records this at *debug* level only), every `python src/main.py <verb>` fails with `✗ AF_UNIX sockets are unavailable on this platform`, and `tui_ratatui.tui_available()` returns False so the ratatui frontend is disabled and the Rich TUI is used instead. Linux and WSL are unaffected (WSL runs a Linux interpreter). The shared suite now skips its socket tests on such an interpreter and pins the degradation on every platform in `tests/shared/test_control.py::TestUnsupportedTransport`; `docs/control_api.md`, `README.md` and `AGENTS.md` state the limitation. To close it, add a non-AF_UNIX transport for Windows — realistically **TCP on 127.0.0.1** with a per-user port and a token file in `tempfile.gettempdir()` (stdlib only, so the model-free shared tests keep working), or `\\.\pipe\vt-control-<user>` via pywin32 (new dependency, and it would not run in CI). Needs a design decision before implementation.

- [ ] **Consolidate the weights onto the revision-keyed bundle tag (one ~2.9 GB upload — do it from a fast connection, not a tethered/metered one).** `src/model_download.py` now resolves weights from `model-cohere-<rev12>` (derived from `REVISION`) and **never** from `/releases/latest`; `LEGACY_RELEASE_BASE` (`.../download/v1.1.0`) currently serves revision `49988892…` and is byte-identical to what the bundle tag would hold, so **nothing is broken today and no upload is urgent**. Run `DRY_RUN=1 ./scripts/publish_model_bundle.sh` (inside the dev shell) to see the plan, then run it for real to publish `model-cohere-499888924f5f` and delete `LEGACY_RELEASE_BASE`. It becomes **mandatory** the next time `REVISION` changes: bumping `REVISION` renames the tag, and until that new tag is published every candidate 404s on `cohere-transcribe-<new-rev>.SHA256SUMS` — including the legacy pin, because the manifest name embeds the revision — leaving first-run installs with no weights at all. **Sequencing matters:** commit and push the code that *reads* the bundle tag first, then publish the bundle, then remove `LEGACY_RELEASE_BASE`. Publishing before the push is pointless (no client looks for the tag yet); removing the pin *before* the bundle is published leaves every fresh install with no weights at all, because the pin is what currently serves revision `49988892…`.
