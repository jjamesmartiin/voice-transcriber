# Known limitations and verification log

This is the project's engineering log, kept in the open rather than in a private
notebook. It records two things: **what is verified on which platform** (and,
just as importantly, what is *not*), and the open gaps with the evidence behind
them.

Read it when you want to know how much to trust a claim. Several entries say
exactly what has and has not been proven — "verified end-to-end on Linux,
expected but unconfirmed on macOS, unreachable on native Windows" — and say why.
That honesty is deliberate: a feature that is unverified on your platform is
different from one that is broken, and you deserve to be able to tell which you
are looking at before you file an issue.

`- [x]` items are kept for the record of *how* something was validated, not as a
changelog; see [`CHANGELOG.md`](../CHANGELOG.md) for what shipped in each release.

> **Looking for the feature-parity work (formatter, diarization, ASR bake-off)?** That has its
own resumable task list: [`TODO-parity.md`](TODO-parity.md). This file stays what it is — the
limitations and verification log.

- [x] **Native Windows has no control API, and no ratatui frontend.** `control.socket_supported()` is `hasattr(socket, "AF_UNIX")`, and **stock CPython on Windows never exposes `AF_UNIX`** — the OS has supported it since Windows 10 1803, but CPython's PR ([bpo-33408](https://bugs.python.org/issue33408)) is still unmerged. Consequences on a native Windows host: the engine does not bind the control socket (`src/main.py` records this at *debug* level only), every `python src/main.py <verb>` fails with `✗ AF_UNIX sockets are unavailable on this platform`, and `tui_ratatui.tui_available()` returns False so the ratatui frontend is disabled and the Rich TUI is used instead. Linux and WSL are unaffected (WSL runs a Linux interpreter). The shared suite now skips its socket tests on such an interpreter and pins the degradation on every platform in `tests/shared/test_control.py::TestUnsupportedTransport`; `docs/control_api.md`, `README.md` and `AGENTS.md` state the limitation. To close it, add a non-AF_UNIX transport for Windows — realistically **TCP on 127.0.0.1** with a per-user port and a token file in `tempfile.gettempdir()` (stdlib only, so the model-free shared tests keep working), or `\\.\pipe\vt-control-<user>` via pywin32 (new dependency, and it would not run in CI). Needs a design decision before implementation.

- [ ] **The formatter's server port is a local trust boundary, not an authenticated one — accepted risk, not a blocker.** Spawn mode hands llama-server a loopback TCP port, and any process on the machine can share that port and answer `/health` for us; every transcript that resolves to it is then POSTed to that process. **What the two guards actually buy:** `_free_port` picks randomly instead of the kernel's sequential choice (so the port cannot be guessed and held in advance), and `_ensure_server` withholds trust from a healthy answer until the child has survived 0.2 s. That defeats a squatter which takes the port with `SO_REUSEADDR` alone — llama-server's bind then fails and its exit is the tell. **What it does not buy:** cpp-httplib sets `SO_REUSEPORT` before binding (`httplib.h`, `#ifdef SO_REUSEPORT`), so a squatter that also opts into `SO_REUSEPORT` **shares** the port — the child's bind succeeds, the child stays alive, and the kernel spreads connections across both listeners. Verified end-to-end against the real binary, the real GGUF and the module's own `format_text`: packets of the conversation went to a process that joined *after* the server was warm, with no race and no need to predict the port (it is readable from `/proc/net/tcp` or `ss`). `--reuse-port` is documented as default-disabled, but the vendored httplib sets it regardless. **Threat model, which is why this stays accepted:** every variant needs a process already running on the same machine. Running as *you*, it can read whatever you can, so this adds little; the case that matters is a **shared host**, where another local user gains capture they otherwise could not reach. **The fix, when it is worth doing:** bind **AF_UNIX instead of TCP** — `llama-server --host <path ending in .sock>` works (verified: it prints `setting address family to AF_UNIX` and serves `/health` over `AF_UNIX`), so the socket can live in a `0700` directory and no other user can connect at all. That is spawn-mode-only, needs no HAL branching, and removes the class rather than detecting it. **Not done here because** it changes the released spawn path and spawn mode is Unix-shaped by nature: cpp-httplib's AF_UNIX support on Windows is unverified, and Windows AF_UNIX socket files carry no filesystem permission guarantee, so Windows would need either its own answer or to keep TCP. The alternative — verifying that the PID owning the listening socket is our child (`/proc/net/tcp`→inode on Linux, `lsof -t` on macOS, `GetExtendedTcpTable` on Windows) — needs a new `src/hal.py` capability that CI can pin structurally for only two of three platforms, so AF_UNIX is the better bet. Parsing llama-server's `"listening on"` stderr line was considered and rejected: it couples the formatter to upstream log text. `--api-key` does not help — a squatter sharing the port reads the key out of our own request. Winning a share does not yield arbitrary typed text: `formatter.validate()` still requires every output token to come from the input. Pinned by `test_a_squatter_that_shares_the_port_is_NOT_detected`, a characterisation test that fails the day this is closed. **Windows is worse, and by a different mechanism:** Winsock's `SO_REUSEADDR` lets a second socket bind an address another socket is already listening on (exactly what `SO_EXCLUSIVEADDRUSE` prevents), and both `http.server` and cpp-httplib set it, so on Windows even an *exclusive* squatter coexists with llama-server — the child binds alongside it, stays alive, and the settle check has nothing to detect. `test_a_squatter_that_cannot_share_the_port_is_not_trusted` is therefore skipped on Windows (`NO_UNSHAREABLE_SQUATTER`), and the mitigation should be assumed absent there: AF_UNIX is the only fix that helps on all three platforms.
