# Audit — 2026-10-11: the formatter transport, the red 1.4.0 matrix, and the new hardening

A [ponytail](https://github.com/DietrichGebert/ponytail)-style audit of the
uncommitted work on the formatter transport plus the security-relevant commits
from 2026-10-10 and 2026-10-11. Three parts:

1. what the red 1.4.0 CI matrix actually was, including the one failure the
   transport fix did not explain;
2. every security-relevant defect found, with severity, whether it was
   *introduced* by the recent commits or **pre-existing in the same class**, and
   the test that now pins the fix;
3. what was found and deliberately **not** fixed, with the recommended fix.

Method: `git show` on each commit, reading the resulting source, and running
things. Every claim below was reproduced locally except where it says otherwise.
The audit itself changed nothing; the fixes it describes are in the tree, each
with the test that pins it.

---

## 1. The red 1.4.0 matrix

### 1.1 Five failures: the health probe read only the head

`7575196` replaced `http.client` (which reads `Content-Length` bytes) with a
hand-rolled reader that stopped at `\r\n\r\n`. That was done to consult no proxy
and no resolver, which is correct — see §2.1 — but it made `/health` depend on
the response body arriving in the **same TCP segment** as the headers. Linux
coalesced; macOS and Windows did not, so `_health_ok` parsed an empty body,
reported a healthy `llama-server` as dead, and every spawn-mode test that waits
for health failed or burned its 20 s timeout.

Fixed by the `_read_response` rewrite already in the tree: it honours
`Content-Length`, falls back to the HTTP/1.0 close-to-signal-EOF rule, enforces a
whole-request deadline rather than an idle gap, and caps head and body. Pinned by
the `RawServer` tests in `tests/shared/test_formatter_llama_server.py`, which
produce the segmented shapes `http.server` cannot.

### 1.2 The sixth failure: the request budget was charged for the cold start

`test_the_module_entry_point_formats_through_the_real_backend` failed on **both**
macOS and Windows while the spawn-mode tests passed elsewhere in the same run —
an asymmetry the segmented-read bug does not explain. The most likely cause, and
the one reproduced here, is this:

`formatter.format_text` measured `elapsed = time.monotonic() - started` around
`module.format_text(...)`, and that call includes `_ensure_server`: process
spawn, and a real model load. It then discarded a *successful* rewrite whenever
`elapsed > timeout_s`, and `DEFAULT_TIMEOUT_S` is **3.0 s**. On a checkout
nothing calls `formatter.warm()`, so the first utterance of every session, and
every utterance after a kill-on-timeout restart, paid the cold start inside that
budget. Anything slower than 3 s — the *normal* case for a 462 MiB GGUF, and
plausibly the case for a cold Python spawn on a slow CI runner — returned the
unformatted text with no error.

Reproduced locally by making the stub take 3.4 s to become healthy:

```
module-level: 3.47s -> 'buy milk'      # old: correct rewrite discarded
second call : 0.00s -> 'Buy milk.'
```

It hid because it fails *open*: the caller's contract is "the formatter may fail;
dictation may not", so the only visible symptom was text that looked unformatted.

**Fixed** in `formatter.format_text`: the backend is warmed *before* the clock
starts, and availability is re-checked before the real call (a warm that failed
arms `llama_server`'s spawn cooldown, so re-checking catches it and avoids paying
a second full spawn timeout). Guardrail 6 keeps its meaning — it now measures the
request, not the backend's readiness. Pinned by
`test_guardrail_6_a_cold_backend_is_not_charged_for_its_own_startup`
(proven to fail against the previous code) and
`test_a_failed_warm_does_not_pay_for_a_second_spawn`.

**Note on the diagnosis added earlier today:** the `direct = backend.format_text(...)`
assertion added to that test warms the backend before the module-level call, so it
would have made the test pass *for the wrong reason* and left this bug in
production. It is kept — it names the failure instead of leaving an output
mismatch — but the cold-start case is pinned by its own test, not by that call.

### 1.3 Test-harness defects found on the way

* `_start_stub` sent the stub's stderr to `DEVNULL` and then reported a bare
  `"stub server never became healthy"`. That message destroyed the evidence
  behind three consecutive undiagnosable CI runs. It now keeps the log and
  includes the last 400 characters in both failure messages.

### 2.1–2.3 The formatter/SLM transport (`llama_server.py`, `post_processor.py`)

`urllib.request` consults `http_proxy` / `HTTPS_PROXY` / macOS `_scproxy`, none of
which can tell `localhost:8000` from the open internet — so on a machine with a
proxy configured, dictation was forwarded to it while the README claimed the
pipeline talks only to `127.0.0.1`. Both loopback paths now bypass the proxy:
the formatter with a raw `socket` that consults nothing, the SLM with
`build_opener(ProxyHandler({}))`. The SLM's `/v1/models` discovery also ignored
`VT_VLLM_URL` (hardcoded port 8000), so on any other port it silently fell back
to a hardcoded model name; it is derived from the chat URL now.

Attach mode additionally refuses: a non-`http://` URL, an `https://` URL (there
is no TLS here, so honouring the scheme meant posting plaintext to port 80), and
any host that is not loopback unless `VT_FORMATTER_ALLOW_REMOTE=1`. The loopback
check decides without a resolver, so a hostile DNS answer cannot steer it, and it
fails safe on every alternative spelling tried (`0.0.0.0`, `localhost.`, decimal
`2130706433`, octal `0177.0.0.1`, `user@host`, `127.1`).

Pinned by `tests/shared/test_slm_loopback.py` (a real endpoint *and* a real proxy,
asserting only the endpoint is used) and the attach-URL tests in
`test_formatter_llama_server.py`.

**Residual, documented:** the SLM pass has no loopback restriction at all —
`VT_VLLM_URL` is wherever you point it. README and `docs/offline_install.md` now
say so instead of claiming otherwise. See §3.6.

### 2.4 Model snapshots are no longer loaded from the launch directory

`transcribe_cohere.load_model` searched `<cwd>/models/cohere` and accepted any
directory containing a `model.safetensors`, then loaded it with
`trust_remote_code=True`. A `config.json` plus `modeling_*.py` dropped in
whatever directory the app happened to be started from therefore executed as the
user — the same CWD-trust hole `db13b26` closed for configuration, in its worst
form. The search is now anchored to the frozen bundle, the checkout and the
per-user data dir, and extracted into `_candidate_model_dirs()` so it can be
tested. Pinned by
`test_audit_regressions.py::TestConfigResolutionIsolation::test_the_cohere_loader_does_not_search_cwd`.

### 2.5 The code-selection files are pinned too

`cdfff33` pinned the four `.py` modules but not `config.json`,
`processor_config.json` or `preprocessor_config.json` — and `config.json` is what
carries the `auto_map` that `trust_remote_code=True` resolves. Pinning the module
files while leaving the pointer to them unpinned closed nothing: a rewritten
`config.json` names any module it likes. All three are in the `digests` map now,
verified byte-identical to the HF snapshot at the pinned revision
(`499888924f5f1313b48ab0686c8f3a94178a4709`) and to the five hashes that were
already pinned. Pinned by the extended `test_cohere_digests_contain_code_files`.

### 2.6 Tar extraction: the name check was not enough

Both no-`data_filter` fallbacks (Python 3.10.0–3.11.3; `pyproject.toml` allows
`>=3.10`) validated only `member.name` lexically and then called `extractall`. A
symlink member pointing outside the destination followed by a regular member
written *through* it passes every name check — CVE-2007-4559. Verified against
the real function with `tarfile.data_filter` deleted: the file landed **outside**
the destination; with the new guard the same archive is refused and the target
file is untouched.

Both installers (local bundle, split parts) now share one
`_check_tar_members` that rejects anything that is not a plain file or directory.
Pinned by
`test_extract_bundle_archive_rejects_tar_links` (it asserts the victim file still
reads `"original"`), alongside the existing traversal tests.

### 2.7 The dictionary loader no longer reads CWD files

`post_processor.load_merged_dictionaries` began all three candidate lists with
CWD-relative paths and `break`s on the first existing file. A
`config/dictionary.yaml` in the launch directory therefore won outright over the
checkout's and the per-user one — anyone able to drop a file in a shared or
downloaded directory silently rewrote the substitutions applied to the user's
dictation (and could point `dictionary_file` at any path via a CWD
`config.yaml`). The candidates are anchored now, exactly as `t2.get_config_file`
and the dictionary CLI already were. Pinned by
`test_a_dictionary_in_the_launch_directory_is_ignored`.

### 2.8 The control endpoint file is replaced, not written through

`_write_endpoint_file` used `os.open(path, O_CREAT | O_TRUNC, 0o600)` on a path
in the **shared temp dir**. Another local user could pre-create it as a symlink
(the open follows it, truncating and overwriting an arbitrary victim file) or as
a world-readable file (the token is readable until the later `chmod`). It now
writes a private `mkstemp` and `os.replace`s it into place, so the *name* is
swapped and nothing is ever written through whatever was there.
`read_endpoint_file` also rejects a JSON `true` port (`isinstance(True, int)` is
`True`) and a non-string host. Pinned by
`test_a_planted_endpoint_path_is_replaced_not_written_through` and the extended
corrupt-endpoint test.

## 4. What is still unverified

* **The Windows and macOS CI jobs.** Nothing here was run on either platform.
  §1.2 is reproduced locally and explains the observed asymmetry, but only the
  four-OS matrix can confirm it. If a job is still red, the test now names its
  own cause (§1.3) instead of failing four times to a bare "never became
  healthy".
* **The tar link guard on an older Python.** Verified on 3.13 with
  `data_filter` deleted; the fallback is what the CI matrix would need to run to
  be certain.
* **A Windows host for §2.4 and §2.8.** Both fixes are cross-platform, but only
  the Linux path was executed. `_candidate_model_dirs()` keeps the frozen-bundle
  insertion order byte-for-byte, and the endpoint write uses `os.replace`, which
  is atomic on Windows.
